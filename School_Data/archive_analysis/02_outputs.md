## التوصيات المسموحة فقط

| التوصية | متى تُستخدم |
|---|---|
| `دمج_مرشّح` | درجة نصية عالية **و** بوابة تشغيلية `pass` — يُرجَّح أنهما نفس النموذج؛ **ليس** دمجاً منفّذاً |
| `مراجعة_بشرية` | 70–89% نصي وبوابة ناجحة، أو حالة حدّية تحتاج حكماً |
| `same_template?` | هيكل مشترك / تشابه متوسط **أو** درجة عالية مع **فشل** البوابة التشغيلية — وظيفة مختلفة أو غير محسومة |
| `إبقاء_منفصل` | تشابه ضعيف أو اختلاف تشغيلي واضح يستدعي الإبقاء صراحة |
| `أجزاء_ملف_واحد` | عناصر من نفس `external_*` تبدو أقساماً داخل ملف واحد لا تكراراً عبر الأرشيف |

### الفرق العملي في التقرير (توضيح 2)
- **`same_template?`**: «نفس الهيكل، ليستا نفس الوظيفة» → مرشّح لتوحيد القالب لاحقاً (خ9) **دون** دمج السجلات.
- **`دمج_مرشّح`**: «يُرجَّح نفس النموذج التشغيلي» → مرشّح لدمج العدّ/النسخ بعد مراجعة بشرية ثم اعتماد لجنة التميز في خ9.
- عمود **`reason`** يجعل الفرق قابلاً للتدقيق سطراً بسطر.

## ما لا يُنتج / لا يُسمح

- لا مخططات JSON واجهات · لا شاشات.

## تقرير إلزامي في 02_duplicates_report.md
1. أزواج ≥90% نصي مع بوابة pass / fail (عددان منفصلان).
2. أزواج 70–89%.
3. عدد `same_template?` مقابل `دمج_مرشّح` مع أمثلة `reason`.
4. أمثلة «تشابه نصي عالٍ + اختلاف تشغيلي» إن وُجدت.
5. هل يُقترح تعديل الخط الأساس؟ إن نعم: الرقم + السبب (بعد اعتماد بشري فقط).
